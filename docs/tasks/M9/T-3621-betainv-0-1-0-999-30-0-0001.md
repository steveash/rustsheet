  plus T-3529's harness commits; excel-graph evidence). `scripts/exit_owners.py`'s `owned` rule over every failing cell,

  within 15 digits (`NumericClose`), so `defer: phase-1b` (decision 0114, decision 0188 R5).
- Excel 0.0033963068798590146, ours 0.0033963068798590124 (5 ulp low). 50-digit mpmath: the root of
  I_x(0.999, 30) = 0.1 is 0.0033963068798590146318... after the A = -0.0001, B = 1 scaling. Excel's value is the
  correctly rounded root scaled in doubles: every order of `A + x (B - A)` on the correctly rounded unscaled root gives
  Excel's double, and each ulp of the unscaled root moves the result by one ulp. So ours misses in the unscaled
  quantile, not the scaling.
- Excel's BETA.INV solves Excel's own BETA.DIST to the crossing (statistics.md "BETA.INV solves Excel's own CDF to the
  crossing (T-1745)"), so the first thing to check is our BETA.DIST cdf at a = 0.999, b = 30 around x = 0.0034 (bratio's
  branch there, crates/rustsheet-engine/src/functions/statistical/bratio/) against the 50-digit value, then the
  search's last bracket in inverse_beta.rs. If the cdf is the cause and an open BETA.DIST task owns that branch, record
  the cell there and close this as moved.
- No sweep is needed to diagnose: Excel is the correctly rounded value, so the target is the math (an accuracy fix,
  never a fit to Excel's bits).
