## Goal
Probe PRs that add visibly-off cases stay mergeable after `main` moves, and PRs stop conflicting
on the visible-parity lock: the lock holds each case to its own count instead of one total.

## Context
- `eval/baseline/visible-parity.json` held one number (decisions 0088, 0093). A probe PR whose new
  visibly-off cells fit in `main`'s slack recorded no rise, and its CI passed. Later, `main` used
  up that slack or the steward lowered the cap, and the PR's merge failed `check` (2,535 against
  2,427). The PR's cases were no longer new, so a re-record could not fix it. Every PR that raised
  the number also conflicted with every other such PR. On 2026-10-31 about 9 PRs were ejected
  from the merge train this way.
- Code: `crates/rustsheet-eval/src/visible_parity.rs` (`Lock`, `VisibleCount`, `judge`),
  `visible_parity_gate` in `crates/rustsheet-eval/src/main.rs`, `scripts/merge_ready.py`
  (`checked_baselines`, `new_failures`) and `scripts/merge_catchup.py`.
- The repository owner asked for this change on 2026-10-31 (decision 0217).

## Acceptance criteria
- [x] `eval/baseline/visible-parity.txt` has one sorted `case<TAB>count` line per case with
      visibly-off in-scope cells, generated by `rustsheet-eval update-baseline`. The json is
      removed.
- [x] `check` fails a case above its line (a case with no line allows 0), and prints each such
      case and the total.
- [x] `update-baseline` writes new cases' lines, raises an existing case only with
      `--allow-regressions`, and lowers or drops lines only with `--lower-visible-lock`.
- [x] `merge_ready` checks the file as an eval-gated list and refuses a carry with a line above
      `main`'s for a case `main` has. `make catch-up` resolves a conflict on the file three-way per
      case and refuses a result above `main`'s line. Python tests cover both.
- [x] `update-baseline --new-cases <file>` treats only the listed cases (ids or case file paths)
      as new. `make catch-up` passes the case files the PR adds. A carry may add or raise a
      line only for a case whose case file `main` lacks. Tests cover both.
- [x] Rust unit tests: a rise in an existing case fails; a new case without a line fails; update
      records a new case; lowering happens only with the flag; the format is one line per case.
- [x] Docs: quality-gates.md, eval-harness.md, the steward skill, Makefile help; decision 0217.
- [x] `make check` green; reviewers approve.

## Out of scope
- Counting cases whose checked-cell count changed as new (today's notion is kept: absent from the
  suite's baseline).

## Outcome
The lock is now per case, in `eval/baseline/visible-parity.txt`: 2,499 cells in 269 cases after
merging main (b98b3c00d), generated with `update-baseline --allow-regressions --lower-visible-lock` while
every suite baseline showed 0 regressions. The old cap was 2,509. `judge` returns the cases over
their lines, plus the lock to write. Lines of removed cases are dropped on update. The merge
tooling treats the file as an eval-gated list: `visible_lock.visible_rises` refuses a raised or
new line in a carry, and `visible_lock.merge_visible` resolves conflicts in `make catch-up`.
After the owner's follow-up, `update-baseline --new-cases <file>` (`make eval-baseline
NEW_CASES=`) makes the listed cases the only new ones. `make catch-up` lists the files the PR adds
(`visible_lock.added_case_files`), so the five queued pre-lock probe PRs can record their cases'
lines after merging `main`. The carry check (`visible_lock.visible_rises` with `case_on`) accepts
a new or higher line only for a case whose case file `main` lacks. The merge tooling's lock
helpers live in `scripts/visible_lock.py`, which keeps `merge_ready.py` under the file-size limit.
After the #2660 review, catch-up merges the lock three-way per case (`three_way`), so it no longer
undoes the steward's lowerings. The carry, and catch-up before it pushes, hold each of `main`'s
cases to `main`'s line. A listed case that already has a line is not new. A catch-up deletes the
retired json that pre-lock PRs modified, and the carry accepts that deletion. One corpus of lock
lines (`crates/rustsheet-eval/tests/data/visible-lock-lines.txt`) keeps the Rust and Python
parsers in step, and both take ASCII digits only. The suite manifest scan is shared in
`scripts/suite_meta.py`.
Decision 0217 amends 0088, 0093 and 0207, and supersedes 0214.
