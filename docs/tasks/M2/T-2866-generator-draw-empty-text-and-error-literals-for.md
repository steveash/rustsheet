## Goal
`rustsheet-gen` sometimes passes empty text (`""`) and an error value to number- and bool-typed `value`
parameters, so new generated batches cover the `empty_text` and `error` argument kinds that decision 0094's
"across the argument modes" asks of the generated 200 cells per function.

## Context
Gap triage 2026-10-27 (`make eval` on 7bd9090e, report.json `argument_coverage`). Across M2, M5 and M6, the
argument kinds most often missing from every suite are `empty_text` and `error` on number-typed value
parameters (for example DAY.serial_number, INDEX.row_num, LEFT.num_chars, MOD.divisor, OFFSET.rows, EDATE.months,
XMATCH.match_mode: about 90 parameter/kind pairs; the probes T-2861 to T-2865 cover them once, by hand).
The cause is in tools/src/rustsheet_tools/gen/generator.py: `Gen.literal("number")` draws only from
`NUMBER_POOL` (numbers), `Gen.literal("bool")` only TRUE/FALSE, and `Gen.scalar_text` falls back to them for the
118 number parameters of M2-M6 that have no `pool:` in eval/catalog/functions.yaml. Text-typed parameters already
get `""` from `TEXT_POOL`, and `"#N/A"` there is text, not an error. Errors exist as the `errors` pool in
tools/src/rustsheet_tools/gen/pools.py (`NA()`, `1/0`, `#N/A`, `#DIV/0!`, ...), used only where the catalog
asks for it.

Change: in `Gen.scalar_text` (or `literal`), for a `value` parameter of type number or bool without a `hard`
domain, draw `""` with a small fixed share and an entry of `POOLS["errors"]` with another (a few percent each,
named constants beside `POOL_RATE`, with a comment citing this task and decision 0094). Keep everything
seeded through `self.rng`. Generated suites are not regenerated by this task: committed cases keep their
formulas and oracle values; only new batches change.

## Acceptance criteria
- [ ] tools/tests/test_generator.py gains a test that, over a fixed seed and enough draws, a number-typed and a
      bool-typed value parameter each receive both `""` and an error literal, and a `hard`-domain parameter
      (MUNIT.dimension) never does.
- [ ] Any existing test that pins the formulas of a seed is updated deliberately, with the reason in the PR.
- [ ] No file under eval/suites/gen-* changes (a manual check writes to a scratch suite,
      `uv run rustsheet-gen --milestone M2 --count 2 --suite <scratch>`, deleted before committing, and its
      formulas contain a `""` or an error argument in a number position).
- [ ] docs/architecture/synthetic-generator.md §6 (value generators; §6.5 errors) states the new shares.
- [ ] `make check` green; reviewers approve.

## Out of scope
- Running and oracle-filling new generated batches (a follow-up research task once this lands).
- `array`-mode parameters and the domain-specific pools in pools.py.

## Outcome
`Gen.scalar_text` draws `""` (`EMPTY_TEXT_RATE`, 3%) and an `errors` pool entry (`ERROR_RATE`, 3%) for a number- or bool-typed `value` parameter that has no `hard` domain and missed its edge pool. Documented in synthetic-generator.md §6.5. Seed-pinned tests updated deliberately because the extra rng draw moves every unfocused seed: the `test_unfocused_output_is_unchanged` digest was re-recorded, `emitted()` now uses 60 seeds (PHONETIC fell out of 40), and `test_number_enums_are_number_literals` accepts `""`. No eval/suites/gen-* file changed; a scratch-suite run produced e.g. `INDEX(Data!A3:C7,#DIV/0!,...)`. Eval delta: none (no engine change).
