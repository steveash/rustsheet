# 0175 — Readiness markers accept the session attribution footer

- **Status:** accepted (2026-10-30, T-3164). It amends SPEC-0027 section 2 ("The marker").
- **Context:** The first live `make mark-ready` from a session (PR #2337, 2026-10-29) posted the marker, then its
  own read-back failed V1 with `malformed marker: no complete marker block at the end of the comment`. The
  session's GitHub write path appends the attribution footer
  (`\n\n---\n_Generated by [Claude Code](https://claude.ai/code)_`) after every comment body, so the
  `merge-train-ready v1` block no longer ends the comment, and `parse_marker` required it to. Every
  session-posted marker therefore read as malformed: the shadow merger had no candidates, and in `train` mode the
  merger would unlabel every marked PR. The `merge-train-ejected v1` block is written only by the merger and is
  never parsed, so it needs no change.
- **Decision:** `parse_marker` normalizes line endings and removes at most one trailing copy of exactly that
  footer before it looks for the block. Any other trailing text, a second footer or a footer that differs in any
  character is still rejected. The footer has one definition, `merge_ready.FOOTER`; `merge_step`'s step-mode
  read-back (`same_body`) uses it too. V1's author rule is unchanged.
- **Consequences:** Markers posted from sessions, through `gh api` or the MCP tools, verify. The footer is text an
  author with write access already controls, so accepting it lets no one else mark a PR. If the platform changes
  the footer's shape, markers read as malformed again (fail closed) until `FOOTER` is updated.
