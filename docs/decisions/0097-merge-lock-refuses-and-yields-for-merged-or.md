# 0097 — Merge lock refuses and yields for merged or closed PRs

- **Status:** accepted (2026-10-21, T-2285); amended by 0145 (a head waiter whose PR is finished is dropped from the queue, a waiter re-reads a PR's state at most every 10th poll, and a train lock is finished only when its non-empty `prs` all are)
- **Context:** On 2026-10-21 a session kept renewing the merge lock for PR 1410 from 06:33 UTC, when #1410 merged, until at least 06:52. Every renewal reset the 30-minute TTL of 0075, so nobody could take the lock over and two sessions waited; the owner took it over with `--ttl 0`.
- **Decision:** `scripts/merge_lock.py acquire --pr N` refuses to take or renew the lock (exit 3) when PR N is merged or closed, and any acquirer may take over a lock whose PR is merged or closed, whatever its age. The state is one GitHub API read; if it fails, the lock behaves as in 0075.
- **Consequences:** A finished PR can no longer hold the lock, so a session that carries on after its merge cannot block others. Agents treat exit 3 as "this PR is done: stop". The TTL is unchanged. The API read needs network access to api.github.com (a `GH_TOKEN`/`GITHUB_TOKEN` is used when set); without it nothing changes from 0075. Amends 0075; the steward skill's merge-lock paragraph says so.
